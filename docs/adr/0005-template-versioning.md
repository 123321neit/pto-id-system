# ADR 0005. Версионирование шаблонов

## Статус

Принято как принцип, требует детализации перед реализацией.

## Контекст

PTO ID System должна генерировать DOCX/PDF формы исполнительной документации. Формы могут меняться из-за требований заказчика, внутренних стандартов, изменений нормативной практики или доработок шаблона.

Если не версионировать шаблоны, невозможно гарантировать воспроизводимость ранее выпущенных документов.

## Решение

Шаблоны документов должны иметь версии. Сгенерированный артефакт должен знать, из какой версии шаблона и какой версии данных он был создан.

## Принципы

- template version является частью metadata документа или generated artifact;
- изменение шаблона не должно молча менять уже выпущенный документ;
- документ может быть помечен как требующий регенерации на новой версии шаблона;
- генерация должна быть воспроизводимой для зафиксированной пары data version + template version;
- миграция документа на новый шаблон должна быть явной операцией.

## Обоснование

Исполнительная документация требует предсказуемости. Если акт был выпущен по одной форме, система должна понимать, по какой именно. Иначе невозможно объяснить, почему PDF сегодня отличается от PDF, выпущенного ранее.

Версионирование шаблонов также позволяет поддерживать разные варианты форм для разных заказчиков или объектов без разрушения доменной модели.

## Последствия

Положительные:

- воспроизводимость генерации;
- контролируемые изменения форм;
- возможность поддержки нескольких вариантов шаблонов;
- понятная связь между документом, данными и артефактом.

Ограничения:

- нужна модель Template и TemplateVersion;
- нужна стратегия миграции данных между версиями шаблонов;
- нужно решить, где хранятся шаблоны;
- нужно выбрать механизм DOCX templating отдельным ADR.

## Нерешенные вопросы

- Какой формат шаблонов использовать?
- Как описывать placeholders и повторяющиеся блоки?
- Как тестировать шаблоны?
- Как поддерживать шаблоны заказчика и базовые шаблоны системы?

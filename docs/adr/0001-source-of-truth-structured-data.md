# ADR 0001. Source of truth — structured data

## Статус

Принято.

## Контекст

PTO ID System работает с исполнительной документацией, где итоговыми артефактами часто являются DOCX, PDF, реестры и комплекты файлов. В ручной практике эти файлы воспринимаются как основная форма хранения информации.

Для web-системы такой подход создает архитектурную проблему: DOCX/PDF плохо подходят для надежного хранения связей, статусов, версий, валидаций и повторного использования данных.

## Решение

Основным источником истины в PTO ID System являются структурированные данные.

DOCX, PDF, XLSX-реестры, архивы комплектов и печатные формы считаются производными артефактами, которые генерируются из данных и шаблонов.

## Обоснование

Structured data позволяют:

- хранить смысл документов явно;
- связывать акты, работы, материалы, сертификаты и схемы;
- валидировать обязательные поля;
- строить реестры без ручного дублирования;
- повторно генерировать документы;
- отслеживать версии данных и шаблонов;
- контролировать полноту комплекта ИД.

DOCX/PDF не дают надежной модели связей и легко расходятся между собой при ручном редактировании.

## Последствия

Положительные:

- система получает устойчивую доменную модель;
- реестры и документы могут быть согласованы между собой;
- появляется база для проверок полноты и качества;
- возможна воспроизводимая генерация артефактов.

Ограничения:

- нужно проектировать typed data model до генерации файлов;
- импорт существующих DOCX/PDF требует отдельного решения;
- пользовательский интерфейс должен скрывать сложность структурированных данных.

## Нерешенные вопросы

- Какой формат хранения structured data будет выбран?
- Какие поля MVP будут строго типизированы?
- Как обрабатывать ручные изменения в экспортированных файлах?

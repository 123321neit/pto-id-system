# SAMPLE — Registry Ventilation Example
# Source: Реестр вентиляция.doc
# Purpose: domain analysis and future parser/template reference

Этот файл фиксирует структуру и смысл реального примера реестра вентиляции. Это не generated output системы, а reference sample для архитектуры.

---

## 1. Назначение реестра

Реестр является перечнем документации, прилагаемой к акту приёмки законченного строительством объекта капитального строительства.

В примере объект:

```text
«Нежилые помещения № 16-18, 21, 22, 30-37 (нумерация по плану БТИ), расположенных на 3 этаже здания Торгового Центра по адресу: г. Екатеринбург, Тбилисский бульвар, д. 13»
```

Выполняемые работы:

```text
Вентиляция, кондиционирование
```

---

## 2. Главные разделы реестра

Реестр содержит:

1. Перечень исполнителей / подрядных организаций.
2. Перечень исполнительной рабочей документации / комплект рабочих чертежей.
3. Сертификаты, технические паспорта и другие документы качества.
4. Акты освидетельствования скрытых работ и другие акты.
5. Исполнительные схемы и съёмки.
6. Подписант реестра.

---

## 3. Contractor block

Пример строки подрядчика:

```text
ООО «Десятый трест»
Договор поставки с выполнением монтажных и пуско-наладочных работ № 11/01 от 18.11.2025
Монтаж систем вентиляции и кондиционирования
369-2025-02-ОВ от 11.2025
Является членом СРО Ассоциация «Межрегиональная Группа Проектировщиков»...
ИНН: 6670499971
КПП: 667801001
ОГРН: 1216600010252
юр. адрес: 620141, Свердловская область, г. Екатеринбург, ул. Ереванская, стр. 6, оф. 120
факт. адрес: 620141, Свердловская область, г. Екатеринбург, ул. Ереванская, стр. 6, оф. 120
Генеральный директор Щеголев М.Е. согласно Уставу
```

### Architectural meaning

Этот блок должен собираться из:

- current `ObjectTemplate` organization assignments for working projection, or
  exact frozen values from a released revision/package for historical output;
- object-level contract settings;
- work type settings;
- SRO/license fields;
- director/authority fields.

Нельзя хранить этот блок только как текст в реестре. Иначе изменение/переиспользование компании и документов станет невозможным.

## 4. ProjectDrawingSet block

Пример:

```text
Наименование лица осуществляющего строительство: ООО «Десятый трест»
Наименование чертежа проекта: Вентиляция
Шифр, номер чертежа: 369-2025-02-ОВ
Количество листов: 13
```

### Architectural meaning

Это `ProjectDrawingSet`, а не `ExecutiveScheme`.

ProjectDrawingSet — комплект рабочей документации, по которому выполнялись работы.

Исполнительная схема — другой объект: файл/схема фактически выполненных работ.

---

## 5. Certificate block

Колонки:

```text
Наименование документа
Кем выдан документ, срок действия
Регистрационный номер документа
Количество документов, шт.
```

Примеры строк:

```text
Сертификат соответствия на воздуховоды и фасонные элементы Неватом
ООО «Эксперт-С» от 08.06.2023
РОСС RU.НЕ06.Н09413
3
```

```text
Сертификат соответствия на расходные материалы
ООО «Авалон» от 11.10.2024
РОСС RU.32311.ОС04.СС01.4805
4
```

```text
Декларация о соответствии на вентилятор ТК 200 Системэйр
BAHÇIVAN HAVALANDIRMA SİSTEMLERİ VE ELEKTRİK MOTОRLARI SANAYİ VE TİCARET ANONİM ŞİRKETİ от 16.08.2023
ЕАЭС № RU Д-TR.РА06.В.53550/23
2
```

### Architectural meaning

Certificate block должен собираться из Certificate Library.

Каждая строка должна ссылаться на физический файл сертификата/декларации/письма.

Нельзя допускать сценарий, где номер сертификата есть в акте/реестре, но нет файла в библиотеке.

## 6. Acts block

Колонки:

```text
Наименования исполнительных документов в хронологическом порядке
Регистрационный номер исполнительных документов
Дата оформления исполнительного документа
Примечание
```

Примеры строк:

```text
Акт освидетельствования скрытых работ. Монтаж воздуховодов систем вентиляции П4, П5, В12, В13, В14 с установкой оконечных устройств в осях 2-9/Б-Ж на отм. 0,000 (3 этаж)
№ ОВ-1
08.04.2026
```

```text
Акт освидетельствования скрытых работ. Монтаж изоляции систем вентиляции П4, П5, В12, В13, В14 в осях 2-9/Б-Ж на отм. 0,000 (3 этаж)
№ ОВ-2
08.04.2026
```

```text
Акт технической готовности на системы общеобменной вентиляции П4, П5, В12, В13, В14
№ ОВ-4
08.04.2026
```

### Architectural meaning

Acts block должен собираться из Document Aggregate.

Source fields:

- document type;
- work description;
- rendered number;
- date;
- status;
- note;
- revision.

---

## 7. Executive schemes block

Колонки:

```text
Наименования исполнительных схем и съемок
Регистрационный номер
Дата оформления
Примечание
```

Пример:

```text
Исполнительная чертеж. Фрагмент плана на 3 этаже
№ 1
08.04.2026
```

### Architectural meaning

ExecutiveScheme = file + structured metadata.

Поля:

- title;
- registration_number;
- date;
- sheet_count;
- note;
- file_id.

---

## 8. Signer block

Пример:

```text
Щёголев М.Е.
Генеральный директор ООО «Десятый трест»
```

### Architectural meaning

Signer block должен собираться из:

- RegistrySignerSnapshot;
- resolved organization/representative library assignment;
- selected representative.

Подписант реестра может отличаться от подписантов актов.

---

## 9. Color logic from user discussion

Пользователь пояснил цветовую логику реестра:

- жёлтый — объектные данные, заполняются один раз на объекте;
- красный — сертификаты и документы качества;
- серый — акты;
- зелёный — исполнительные чертежи/схемы;
- тёмно-красный — лицо, которое подписывает реестр.

---

## 10. Final architectural conclusion

Реестр нельзя проектировать как главный editable table.

Правильная модель:

```text
Object + ObjectTemplate assignments + ProjectDrawingSet + Certificates + released/current Documents + ExecutiveSchemes + RegistryOverrides
→ Registry Projection
→ DOCX/PDF Registry Artifact
```

Реестр всегда должен быть пересобираемым.
Historical registry/package output must use frozen released dependencies rather
than re-resolving current library values.

# ADR 0003. Реестр — производная проекция

## Статус

Принято.

## Контекст

В работе ПТО реестр часто выглядит как главный рабочий инструмент. В нем видны номера актов, даты, статусы, сертификаты, схемы и состав комплекта. Поэтому есть риск сделать реестр основной таблицей системы.

Такой подход повторяет Excel-процесс и приводит к дублированию данных.

## Решение

Реестр в PTO ID System является производной проекцией над доменной моделью.

Он строится из:

- документов;
- typed document data;
- работ;
- материалов;
- сертификатов;
- исполнительных схем;
- статусов;
- комплектов;
- связей между сущностями.

## Обоснование

Реестр должен отвечать на вопрос «что сейчас есть и в каком состоянии», а не хранить всю правду о проекте.

Если сделать его source of truth, система потеряет связи между документами и начнет зависеть от строк и колонок. Это усложнит проверки полноты, генерацию документов и обновление связанных данных.

## Последствия

Положительные:

- реестр всегда согласуется с документами;
- можно строить разные реестры из одной модели;
- экспорт реестра не ломает данные;
- проверки строятся по связям, а не по тексту ячеек.

Ограничения:

- нужно спроектировать projection layer;
- редактирование через реестр должно изменять structured data;
- материализованные представления требуют стратегии пересчета.

# ADR 0002. Typed documents вместо generic documents

## Статус

Принято.

## Контекст

Исполнительная документация состоит из разных типов документов: АОСР, актов испытаний, сертификатов, исполнительных схем, реестров и комплектов. Внешне они могут быть похожи на наборы полей и таблиц, но семантически это разные объекты.

Есть риск построить систему как generic document constructor, где любой документ — произвольная форма с произвольными блоками. Такой подход упростит первый экран, но разрушит доменную модель.

## Решение

PTO ID System использует typed documents.

Каждый ключевой тип документа имеет собственную модель данных, обязательные поля, связи, правила валидации и генерации.

## Примеры

АОСР должен знать:

- какую работу он освидетельствует;
- какие материалы применены;
- какие сертификаты подтверждают материалы;
- какие исполнительные схемы связаны с работой;
- кто участвует в подписании.

Акт испытаний должен знать:

- что испытывается;
- по какой методике;
- с какими параметрами;
- какой результат получен;
- какое заключение зафиксировано.

Сертификат должен знать:

- какой материал или оборудование подтверждает;
- номер, дату, производителя, партию;
- в каких документах применяется.

Исполнительная схема должна знать:

- к какой системе и участку относится;
- какие работы подтверждает;
- с какими актами связана.

## Обоснование

Typed documents позволяют системе понимать предметную область. Это нужно для:

- проверки полноты;
- построения реестров;
- генерации корректных форм;
- связывания документов;
- сборки комплектов;
- будущей аналитики и контроля ошибок.

Generic documents оставляют только форму, но теряют смысл.

## Последствия

Положительные:

- доменная модель остается выразительной;
- система может проверять данные;
- документы становятся связанными, а не изолированными файлами.

Ограничения:

- для каждого типа документа нужно проектировать модель;
- нельзя быстро добавлять произвольные формы без анализа;
- расширяемость должна быть управляемой.
